## 三分钟介绍骨架

我做的是一个基于 vLLM 的原生缓存策略扩展。长系统上下文在多轮调用中反复出现，但一次性请求会污染 LRU。
我把冻结实验行为移入原生 BlockPool，增加有界 Two-Queue，并保持引用/哈希所有权留在上游池。
实现包括 CLI 到缓存池的配置传递、明确拒绝不支持组合、指标导出、差分和生命周期测试，以及固定 Agent 轨迹采集。
已有 48 项原生测试和 15,000 状态比较，并完成两模型四场景及并发/断连/抢占恢复。
7B 的构造扫描后，LRU 热点命中 0%，Two-Queue 约 99.48%；其它场景和 0.5B 负结果保留，不说整体生产提速。

## 核心追问

1. 为什么空闲仍能命中？ref=0 表示没人持有，缓存身份不必立即清除。
2. 活动块被降级能否淘汰？不能。降级只撤保护，引用未归零不进空闲队列。
3. 取消共享请求怎么办？只释放自己的引用，不能影响其它持有者。
4. 冷区耗尽怎么办？回退热区，保护不是永久 pin。
5. 同哈希多副本怎么处理？只删被重用的 block_id 索引。
6. reset 何时拒绝？仍有活动普通块时，且拒绝不得改变状态。
7. 为什么累计指标求差？5、5、8 只能新增 5、0、3。
8. 90.1% 是什么？单次 7B 构造里扫描后 5 探测的 HTTP mean 相对下降，不是 TTFT 或生产总提速。
9. 为什么不写完整 ARC？没有 ghost/adaptive history；保护额度固定。
10. 为什么 48 项不是全部正确？只覆盖两份测试文件，服务测试也没有穷尽所有竞态或 KV 数值。
